# FLOODLIGHT — نصب و وضعیت

## نصب

از پوشهٔ `football_project` (همان جایی که `football_engine/` هست):

```powershell
# فایل‌ها را کپی کن (پوشه‌ها merge می‌شوند، چیزی پاک نمی‌شود)
xcopy /E /I /Y football-engine-ui\football_engine football_engine
xcopy /E /I /Y football-engine-ui\data data
xcopy /E /I /Y football-engine-ui\web web
xcopy /E /I /Y football-engine-ui\tests tests
xcopy /E /I /Y football-engine-ui\tools tools
copy /Y football-engine-ui\selftest.py .
copy /Y football-engine-ui\requirements-api.txt .

python -m pip install -r requirements-api.txt
python selftest.py
```

`selftest.py` هر لایه را جدا اجرا می‌کند و دقیقاً می‌گوید کجا شکست. **اول این
را اجرا کن**، بعد سرور را بالا بیاور:

```powershell
python -m uvicorn football_engine.api.app:app --reload
```

## چه چیزی ساخته شد

### ۱. پست‌های متعدد برای هر بازیکن ✅

`data/normalized/players/player_positions.json` — برای هر ۳۹۶ بازیکن یک مجموعه
پست. از role اصلی + attributeهای خود بازیکن استخراج می‌شود، نه با دست:

| بازیکن | پست‌ها |
|---|---|
| Messi 2010/11 | FW · AM · WM |
| Abidal 2010/11 | FB · WM · CB |
| Busquets 2010/11 | DM · CM · CB |
| Xavi 2010/11 | CM · AM |
| Puyol 2010/11 | CB |

قانون استخراج داخل خود فایل JSON ثبت شده. `tools/generate_positions.py`
بازتولیدش می‌کند و بخش `overrides` دست‌نویس همیشه برنده است — هر بازیکنی را
خواستی دستی اصلاح کن.

**یک نکته مهم:** راست/چپ (RB در برابر LB) در engine وجود ندارد — `side` از
جایگاه روی زمین می‌آید نه از خود بازیکن. پس «آلوز راست‌پا است» با جایی که
می‌گذاری‌اش بیان می‌شود، نه با role. پاپای چپ/راست یک feature جداست.

### ۲. Role Fit ✅ — این بزرگ‌ترین gap بود

`football_engine/role_fit/` ضریب‌های E-24 را تأمین می‌کند. قبلاً هر
`fit_factor` عدد خنثای `1.0` بود؛ یعنی مهاجم در قلب دفاع هیچ جریمه‌ای نداشت.

- اگر پست assign‌شده در لیست پست‌های بازیکن باشد → `1.0`
- وگرنه با فاصلهٔ موقعیتی افت می‌کند: `FB→WM = 0.83`، `FW→CB = 0.66`
- دروازه‌بانی در هر جهت → `0.40`

**این ریاضیات جدید است.** همهٔ ضرایب در `RoleFitCoefficients` قابل تغییرند و
`/api/role-fit` صراحتاً `calibrated: false` برمی‌گرداند. calibrate نشده‌اند.

### ۳. Draft قرعه‌کشی واقعی ✅

`football_engine/draft/lottery.py` — دقیقاً چیزی که خواستی:

```
۱۱ دور:
  یک باشگاه قرعه‌کشی می‌شود
  تو از همان باشگاه یک بازیکن انتخاب می‌کنی
```

باشگاه را انتخاب نمی‌کنی، داخلش انتخاب می‌کنی. دو حالت: باشگاه‌ها تکرار شوند،
یا هر باشگاه فقط یک بازیکن. با seed یکسان عیناً تکرار می‌شود.

تست شد: تکرارپذیری، ۱۱ بازیکن یکتا، عدم امکان انتخاب خارج از باشگاه قرعه‌شده،
حالت «یک بازیکن از هر باشگاه» → ۱۱ باشگاه متمایز.

### ۴. رابط کاربری ✅

صفحهٔ draft حالا دو حالت دارد: **Lottery** (پیش‌فرض) و **Free pick** (قبلی).
روی زمین، بازیکن خارج از پست طبیعی‌اش با ضریب fit واقعی علامت می‌خورد.

## آنچه ساخته **نشد** — و چرا

### UCL با تیم تو ❌

`football_engine/competition/ucl.py` موجود است ولی **نمی‌تواند تیم draft‌شدهٔ
تو را بپذیرد** — `_simulate_match` فقط `repos.teams.get()` می‌خواند. علاوه بر
این هنگام خواندنش چهار باگ واقعی پیدا کردم:

1. `determine_knockout_winner` تساوی را با `hash(match_id) % 2` حل می‌کند.
   `hash()` روی رشته در هر process تصادفی است → **reproducibility می‌شکند**.
2. متغیر مردهٔ `home_away_goals` با کامنت `# wrong` خود نویسنده.
3. قرعه‌کشی R16 فقط `r16_teams + playoff_winners` پشت‌سرهم است، نه seeding
   واقعی (۱ مقابل ۱۶). کامنت خودش می‌گوید «need proper seeding».
4. فینال مساوی → `champion = final_a` بی‌صدا. پنالتی وجود ندارد.

این یعنی UCL نیاز به یک ماژول جایگزین دارد، نه یک endpoint. کار کوچکی نیست و
من **نمی‌توانستم اینجا اجرایش کنم** تا درست بودنش را ببینم.

### محدودیت واقعی داده ⚠️

از ۳۶ باشگاه، فقط **۲ تا واقعی‌اند**: بارسلونا ۲۰۱۰/۱۱ و چلسی ۲۰۱۱/۱۲. بقیه
۳۴ تا قالب مصنوعی‌اند با نام‌هایی مثل `sporting_0_2015_16` و attributeهای خنثی.

یعنی «draft تاریخی» الان روی ۲۲ بازیکن واقعی می‌چرخد. در UI با برچسب
«Template» مشخص شده‌اند و می‌توانی با تیک `include template clubs` کنارشان
بگذاری — ولی آن‌وقت فقط ۲ باشگاه می‌ماند و draft یازده‌دوره‌ای ممکن نیست.

**هیچ کدی این را حل نمی‌کند.** این همان «۱۰۰۰+ بازیکن» است که خودت در لیست
ناتمام‌ها داشتی. تا دیتابیس بزرگ نشود، بازی همیشه کوچک می‌ماند.
